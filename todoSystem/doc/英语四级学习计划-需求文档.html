英语四级学习计划 · 项目改造需求文档

将一个纯前端单文件 HTML 实现的「半年英语四级学习计划」改造为接入本项目后端（NestJS + MySQL + Redis） 与前端（React + Vite + TypeScript + Tailwind）的正式功能，实现学习数据云端存储、跨设备同步与用户隔离。

来源文件：doc/半年英语四级学习计划.html 目标：todoSystem 项目内建功能 日期：2026-11-19 状态：待评审

01 背景与现状分析

现有 半年英语四级学习计划.html 是一个自包含的静态页面（约 1497 行、550KB，含内联 CSS/JS 与 base64 图片）， 数据以两个大常量硬编码在 <script> 中，全部功能在浏览器本地运行，无任何后端依赖。

1.1 现有数据规模（已核实）

20单元（月）
200学习日
4000独立词条
14影视推荐
20每日词数
  • 单元 / 月：20 个单元，每单元 10 天，主题从「生活与日常」到「综合进阶二」递进。
  • 每日数据：每天 20 个单词，每词 5 元组 [英文, 词性, 中文释义, 英文例句, 例句翻译]。
  • 单元数据：含中英文名称、主题描述、引导语 / 结束语（中英各一），由它们与当天例句拼成每日短文。
  • 影视数据：14 部英语原声影片，含标题、年份、类型、难度、推荐理由、简介、学习建议、经典台词及译文。

1.2 现有功能清单

功能说明实现方式

侧栏目录按单元分组的 200 天列表，单元可折叠展开，显示「学习日 / 周复习 / 月总结 / 已完成」标签buildNav()

1.3 现状局限（改造动因）

  • 进度只存本机 localStorage，换设备 / 清缓存即丢失，无法跨设备同步。
  • 所有内容硬编码在单文件，数据与视图强耦合，难以维护、扩展或做增量更新。
  • 无用户体系，任何打开页面的人共享同一份（其实是各自本地的）进度，无法满足「我的学习计划」语义。
  • 单词 / 例句 / 短文 / 影视数据全量内联，首屏体积大（约 550KB），不利于加载性能。
  • 原文件 HTML 结构末尾存在 </script> 重复闭合的瑕疵，且无状态管理框架、无路由，代码可维护性低。

02 改造目标

  1. 把硬编码的课程数据迁移到 MySQL，由 NestJS 提供 REST API，前端按需读取。
  2. 用户的「完成状态」迁移到后端并按用户隔离，实现跨设备同步；保留本地缓存作为离线兜底（可选）。
  3. 复用项目现有的 JWT 鉴权（全局 AuthModule + JwtAuthGuard），学习进度接口需登录访问。
  4. 用 React + TypeScript + Tailwind 重构界面，保留原有信息架构与学习体验，遵循现有暖纸编辑风设计 token。
  5. 数据只读开放：课程内容面向所有登录用户，进度数据严格按 userId 隔离。
范围边界：本期做「数据上云 + 进度同步 + 前端重构」。新增背单词测试、发音、音频、社交等功能不在本期范围，见第 8 节待确认。

3.1 交互细节

  • 单词卡 / 例句中目标词高亮：由前端根据词条对例句文本做匹配渲染（保留原逻辑）。
  • 周复习自测：默认隐藏答案，点击「显示答案」后揭示，一行独立控制。
  • 单元折叠状态、当前所在天：用 URL 与前端本地状态维护，不落库。
  • 标记完成：调用后端接口切换状态，成功后更新进度条与目录标签；失败回退并提示。

04 数据模型设计（MySQL）

建议以「结构化表」存储，便于检索、统计与后续扩展。字段命名沿用项目现有风格（实体属性名即列名，如 createdAt）。

4.1 units（单元 / 月）

字段类型说明
idint PK AI单元号 1–20
namevarchar(100)中文名，如「第 1 单元 · 生活与日常」
envarchar(100)英文名，如「Unit 1 · Everyday Life」
themetext主题描述
intro / introZhtext引导语（英 / 中）
outro / outroZhtext结束语（英 / 中）

4.2 days（学习日）

字段类型说明
idint PK AI主键
unitIdint所属单元，索引
dayNoint单元内第几天 1–10
globalDayint全局第几天 1–200，唯一索引
themevarchar(100)当日主题

4.3 words（单词）

字段类型说明
idint PK AI主键
dayIdint所属学习日，索引
seqint当日顺序 1–20
wordvarchar(100)英文单词
posvarchar(20)词性，如 n. / v.
meaningvarchar(255)中文释义
exampleEn / exampleZhtext英文例句 / 中文翻译
共 20 × 10 × 20 = 4000 条词记录。搜索功能（按主题 / 英中单词）可基于这些字段做 LIKE 查询，后续量大时再考虑全文索引。

4.4 films（影视推荐）

字段：id, title, cn, year, genre, level, reason, synopsis, tips, quote, quoteZh, sortOrder；共 14 条，按 sortOrder 排列。

4.5 learning_progress（用户学习进度）

字段类型说明
idint PK AI主键
userIdint所属用户，与 users.id 关联，唯一索引 (userId, globalDay)
globalDayint完成的学习日 1–200
createdAt / updatedAtdatetime(6)完成 / 更新时间

仅存「已完成」记录（ toggling 完成时增删行），进度 = 该用户记录数 / 200。与原 localStorage 的 map 语义等价，但按用户隔离、可同步。

4.6 数据迁移

  1. 从原 HTML 中解析 DATA（20 单元 / 200 天 / 4000 词）与 FILMS（14 部）常量。
  2. 编写一次性导入脚本（Node + mysql2），按上述表结构写入；保证幂等（先清空 related 表或按唯一键 upsert）。
  3. 迁移脚本纳入 doc/ 或 backend/scripts/，便于复现；初始化 SQL 追加建表语句到 doc/init.sql。

05 后端 API 设计

新增 StudyModule（controller + service + entities），课程数据接口公开只读，进度接口挂 JwtAuthGuard 并按 userId 隔离（参照现有 TodosModule 的写法）。

Method路径鉴权说明
GET/study/overview否单元列表 + 统计数据（20/200/4000/14 等），用于总览页
GET/study/units否20 个单元（含引导语）列表
GET/study/days?unitId=&dayNo= 或 /study/days/:globalDay否某天详情（主题 + 20 词），用于每日学习页
GET/study/days/search?q=否按主题或单词中英文搜索，返回命中的天列表（供侧栏过滤）
GET/study/films否14 部影视推荐
GET/study/progress是当前用户已完成天数列表 + 总数
POST/study/progress/:globalDay是标记某天完成（幂等，已存在则不重复插入）
DELETE/study/progress/:globalDay是取消完成标记

响应统一使用项目现有的 { code, message, data, timestamp } 外壳；错误由 AllExceptionsFilter 统一处理。课程数据可用 Redis 缓存（参照 TodosService），进度数据不缓存或短 TTL。

06 前端设计

  • 路由：在现有 AppRouter 增加 /study（总览，可公开或登录可见，见待确认）、/study/day/:globalDay、/study/films；/study/progress 相关操作需登录。
  • 目录结构：src/api/study.ts、src/types/study.ts、src/views/study/*、src/components/study/*，沿用现有分层。
  • 状态：课程数据用请求即取 + React 状态 / 可选 TanStack Query；进度状态建议独立 store 或在页面内管理，完成后同步顶部进度条。
  • 视觉：沿用暖纸编辑风 token（paper/ink/accent 等）；原页面的蓝紫配色 (#5b6ee1) 与金色 / 绿色标签语义，映射为项目内既有色板，不引入青色 / 新强调色。
  • 响应式：桌面端左侧固定目录 + 右侧内容；移动端目录抽屉化（原页面已有侧栏，需补充移动端适配）。
  • 加载 / 空 / 错误态：按项目规范，各数据视图需覆盖 Loading、Empty、Error、成功四种状态。

07 非功能需求

  • 性能：课程接口分页 / 按需加载（单元列表与某天详情分离），避免一次性返回 4000 词；列表接口加缓存。
  • 数据一致性：迁移脚本幂等；进度标记接口幂等，防止重复点击产生重复记录。
  • 安全：进度接口强制按 userId 隔离，用户 A 不能读写用户 B 的进度（参照 Todos 的归属校验）。课程数据只读，不接受用户写入。
  • 兼容性：原有 localStorage(eng6m_done) 可作为一次性迁移来源：登录后首次进入时把本地进度合并到后端（可选，见待确认）。
  • 可维护性：数据全部入库，前端不再内联大常量；新增 / 修订词条只需改数据库或管理脚本。

08 待确认问题

  1. 课程总览页是否要求登录？建议：课程数据公开可读，进度相关操作必须登录。
  2. 是否需要把旧版 localStorage 进度一次性迁移到后端？若是，需定合并策略（覆盖 / 并集）。
  3. 是否需要保留「本地离线可用」能力（Service Worker / 本地缓存）？
  4. 无网络时课程数据是否允许前端内置精简版兜底？本期倾向否。
  5. 是否在本期加入背词自测的做题记录 / 正确率统计？倾向否，仅保留原有「显示答案」自测。
  6. 影视数据是否需要外部链接（如播放源）？原文件只有文字信息。
以上问题不影响 P0 功能启动，可在评审会上确认后补充到 v1.1。

09 交付物与验收标准

9.1 交付物

  • 后端：StudyModule（entities / dto / controller / service）、数据迁移脚本、init.sql 追加的建表语句。
  • 前端：学习总览 / 每日学习 / 影视推荐页面、侧栏目录、进度同步、类型与 API 层。
  • 文档：本需求文档、迁移脚本使用说明。

9.2 验收标准

  • 原有 20 单元 / 200 天 / 4000 词 / 14 部影视数据完整迁移，数量与内容一致。
  • 20 词卡、句子跟读、短文阅读、周复习自测、月总结、影视推荐等功能与原页面等价。
  • 搜索、折叠、上/下一天、标记完成、进度条在 React 版本中可用。
  • 不同用户的完成进度互不影响；登录后换设备能看到相同进度。
  • 前后端 npm run build 通过，无类型错误。
本文档基于对源 HTML 的静态分析编写，数据统计（20 单元 / 200 天 / 4000 词 / 14 影视）已通过脚本解析核实。 后续实现以本文档 v1.0 为基线，变更需同步更新版本号与修订记录。
